# StuHelper Media

通用文件模块管理逻辑文件、不可变版本、上传会话和业务引用。课程资料及其他业务负责自己的审核和访问权益；物理副本通过 storage 公开接口管理，供应商账号与凭据由 backend 装配。

## 当前实现

上传用途由服务端配置，固定内容类型、大小和保护要求。上传先进入平台受控实例，通过实际类型、长度和摘要校验后等待业务批准。批准后的公开化保留可核验来源，首次引用发布要求两份健康副本，第三份由 storage 补齐。

引用发布需要当前业务授权。后台可以恢复存储操作，但不能仅凭旧请求自动开放业务引用。下载通过网关，在输出首字节前再次检查引用、停用状态和当前权限；不返回供应商地址或长期签名。

引用释放立即停止对应入口。其他有效引用继续使用同一版本；最后一个引用释放后进入持久化清理。崩溃恢复使用稳定对象键，避免超过请求重放窗口后创建第二个存储对象。

文件清单按上传者分页并检查当前权限。引用可以生成清单或 ZIP 下载包，保存原文件名、版本和摘要；打包逐项重查权限，文件数量、总大小、执行时间与并发均有上限。

## 接入与检查

配置必须明确用途、授权器、存储服务身份、上传期限、未引用保留期限与容量上限。media 使用独立数据库身份及迁移，不得读取 storage 数据表。正式构建设置 GOWORK=off，源码组合由 go.mod 固定。

```bash
make setup
make generate
bash scripts/check-with-postgres.sh
```

检查使用专用、仅本地 socket 的 PostgreSQL，结束清理数据库。普通测试使用供应商和业务授权夹具，不登录真实 BHpan。OpenAPI 先定义接口，再生成 Go 与 TypeScript SDK；生成一致性纳入检查。

具体规则、资源上限和验收场景见[模块规格](docs/spec/media.md)。后台装配与界面由应用仓库负责；Next SSO、贡献激励、受限文件加密和阅读器不在本模块实现。

许可证为 AGPL-3.0-only。

新文件使用 storage 共享内容引用，重复实际上传不会生成另一组同范围、同保护要求的物理副本。创建上传时启用 reuse_existing，可免传输本人相同用途、内容类型和内容标识的已完成文件。复用保留独立版本、文件名、审核及引用，仍检查当前来源权限。

reused 为 true 且状态为 verifying 时，只查询原会话等待恢复。复用成功后新版本进入 awaiting_approval。跨用户仅提交摘要仍需实际上传；旧版对象继续保留原身份，重复执行迁移不会重写历史绑定。
