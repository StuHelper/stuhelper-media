# 通用文件与业务引用

## 身份与状态

文件保持稳定 ID，一个文件最多一百个不可变版本。上传会话绑定版本、上传者、名称、类型、长度和 SHA-256。新版本不替换旧引用；业务显式创建新引用并释放旧引用。跨上传者不能继续添加版本。

用途配置归服务端所有。上传保护要求必须为非公开分类；发布保护要求只能保持该分类，或在同一范围内改为公开。客户端不能选择密级、账号或副本位置。受限文件只使用明确允许明文的平台实例，应用层加密延期。

状态依次为 created、uploading、verifying、awaiting_approval、approved 和 ready。cancelled、expired、rejected、deleting、deleted 停止交付；清理结果单独记录，停止访问不等于远端已删除。

传输读取实际前缀核对 MIME，再由 storage 在供应商写入前核对完整长度和摘要。此校验不代表恶意内容扫描或业务审核。业务批准是独立授权动作，发布保护要求不满足或没有保留来源时保持等待。

## 引用与交付

引用固定到文件版本、所属模块和业务对象。同一绑定不重复创建；引用所属模块须与上传用途一致，跨业务复用另建版本。pending 和 publishing 均不允许读取，active 才可交付，released 不可重新启用。

发布首先保存意图，再检查当前业务授权与两份发布门槛，最后确认引用。崩溃后的重试继续同一意图；后台只恢复存储，不凭历史意图自动授予业务访问权。业务授权接口须检查当前资格与业务状态。

下载仅通过引用网关。存储完成整文件校验后，media 在首字节前再次检查文件停用、引用状态、业务权限和存储分类。响应使用原文件名的安全编码、attachment、no-store 和 nosniff；没有开放直链或离线许可。

停用文件阻止新上传、引用和下载。释放一个引用不影响其他有效引用，最后一个引用释放后删除该版本；仍有引用时拒绝整文件删除。迟到的写入或发布结果不得复活已删除版本。

## 清单与打包

文件清单按上传者分页，单页最多一百项，并逐项检查当前权限。游标按已扫描行推进，权限变化后隐藏的行不会导致重复读取或卡住翻页。列表不包含存储位置和凭据。

下载包仅接受业务引用，默认最多一百份文件、总大小 1 GiB，部署可降低上限。每个文件输出前重新检查当前权限，结束前再次检查整份清单；撤权或传输失败会中断下载，客户端须丢弃不完整文件。

ZIP 使用原文件名和独立编号目录，避免同名覆盖。manifest.json 保存文件名、版本、长度与 SHA-256。打包复用 storage 的有界校验暂存，不保存完整 ZIP，整个请求只占一个传输名额，最长期限仍为五分钟。

## 持久化与恢复

media 拥有文件、版本、引用、任务、请求重放、审计和 outbox。独立运行身份禁止读写 storage 表或修改审计；所有跨模块动作通过 storage 服务接口完成。迁移由运维身份执行，运行入口不自行迁移。

文件内修改串行化，传输不占用长期数据库事务。任务使用持久化租约和执行代次，过期执行者不能确认新任务。稳定存储键绑定服务身份和文件版本，响应丢失、重启或普通重放窗口过期不生成第二对象。

删除先停止本地交付，再释放唯一 media 存储引用并删除已知对象。每次恢复重新核对引用，抵消迟到发布；全部物理副本删除后才确认清理完成。审核和引用事件与本模块状态在同一事务中写入。

## 资源与保留

每个用途明确文件大小和允许类型；单文件上限 1 GiB，传输并发最多 16，单次执行最多五分钟。上传会话一至一千四百四十分钟；未引用内容的保留窗口不超过二十四小时，不超过存储核心的临时对象窗口。

每个身份最多一万个逻辑文件、一百个未完成上传，每文件最多一百版本，每版本最多一百绑定；实际配置可更低。扫描与事件分页最多一百项，重试次数明确配置，耗尽后保留故障状态，不无限重发供应商操作。

本模块不新增文件字节缓存，复用 storage 的有界暂存。逻辑文件、墓碑、幂等记录和审计保留于模块数据库，未提供自动归档删除；配置数据库容量上限后使用，达到限额不得自动扩容。运营归档与历史保留清理须在生产接入前完成。

## 验收场景

测试使用真实 PostgreSQL、隔离角色和可控供应商，真实账号、生产身份接入与部署分别验收。

| 场景 | 预期结果 |
| --- | --- |
| MEDIA-01 | 并发重试产生同一版本，参数冲突被拒绝，错误内容不写入供应商，过期上传可清理 |
| MEDIA-02 | 待审文件不进入贡献账号，批准后达到三副本，引用发布、独立释放与最终删除完整闭环 |
| MEDIA-03 | 文件版本不可变，拒绝跨用户和跨业务绑定；下载期间撤权或停用阻止首字节输出 |
| MEDIA-04 | 重启恢复丢失响应而不重复对象，后台不发布过期同意，重新授权重试后完成同一引用 |
| MEDIA-05 | 模块数据库身份隔离，审计与 outbox 同事务，存在有效引用时拒绝整文件删除 |
| MEDIA-06 | 生成 SDK 完成上传与下载，拒绝客户端密级和未认证请求，正确编码中文名称，不暴露物理位置 |
| MEDIA-07 | 创建响应丢失超过二十四小时后，恢复清理原对象，不创建第二个存储对象 |

| MEDIA-08 | 打包保留原文件与摘要，单并发可完成；撤权、引用释放、重复选择和容量超限被拒绝 |
| MEDIA-09 | 文件分页仅返回当前身份有权读取的对象，隐藏行后游标仍能继续，响应不泄露存储信息 |

审核读取使用独立 media.versions.review 权限，在返回字节前重新检查当前授权和文件保护范围。该读取不批准文件、不激活业务引用，也不改变普通下载的发布条件。

| --- | --- |
| MEDIA-10 | 已校验待审文件可由当前授权审核员读取，撤权立即拒绝，文件仍保持待审状态 |

## 本人内容复用

新上传版本通过 storage 的共享内容引用保存。物理内容按存储服务身份、学校范围、保护要求、摘要、长度和副本策略分组，各版本仍独立保存文件名、上传者、审核和业务引用。旧版本保持原对象身份与恢复方式。

创建上传时可启用 reuse_existing。服务只在本人相同用途、内容类型、大小、摘要和当前用途配置中查找最多十个已完成候选，并重新检查读取权限、停用状态和保留期限。匹配后免传输文件字节，新版本继续等待独立业务审核。

reused 为 true 且状态为 verifying 时，客户端查询原上传会话并等待恢复，不发送文件内容。来源与目标保护要求不同会在服务端校验并迁移内容，同一保护分组复用已有物理副本。响应丢失和重启继续原版本与存储引用。

跨用户仅提供摘要不获得免上传或内容读取。用户实际上传并通过完整字节校验后，相同保护分组可以共用副本。来源权限被撤销、文件停用或用途配置变化时，不再选择来源免上传。

| 场景 | 预期结果 |
| --- | --- |
| MEDIA-11 | 本人重复内容免上传且版本、文件名和审核独立；另一用户仅提交摘要仍需实际字节，校验后只存一组副本 |
| MEDIA-12 | 当前读取权限、停用与配置控制复用资格；结果丢失和重启沿用原上传，不重复传输或自动批准 |
