# 通用文件与业务引用

## 模块边界

media 拥有逻辑文件、版本、上传会话、引用、恢复任务、请求重放、审计和 outbox。独立运行身份使用本模块数据，迁移由独立身份执行。运行程序不自行迁移。

`module.json` 登记 storage 为唯一必需模块，无可选依赖。media 通过 storage 的公开服务接口操作物理副本。装配方提供当前业务授权和可选的源文件保留回调。业务访问权、资料审核和发布规则归所属业务模块。

平台 HTTP 路由和请求、响应结构由 OpenAPI 定义。业务编排可调用 media 的 Go 接口。[OpenAPI 契约](https://github.com/StuHelper/stuhelper-media/blob/develop/contracts/media.openapi.json)

## 上传与审核

文件保持稳定 ID，一个文件最多一百个不可变版本。上传会话绑定版本、上传者、名称、类型、长度和 SHA-256。新版本不替换旧引用；业务显式创建新引用并释放旧引用。跨上传者不能继续添加版本。

用途配置归服务端所有。上传保护要求必须为非公开分类；发布保护要求只能保持该分类，或在同一范围内改为公开。客户端不能选择密级、账号或副本位置。受限文件只使用明确允许明文的平台实例，应用层加密延期。

上传会话从 `created` 开始，接收内容时进入 `uploading`，待核对存储结果时进入 `verifying`。完成校验后为 `awaiting_approval`，批准后为 `approved`，符合发布保护和副本门槛后为 `ready`。免传会话可直接进入 `verifying`。

`cancelled`、`expired`、`rejected`、`deleting`、`deleted` 停止交付，清理结果单独记录。

传输支持整包写入与按偏移分片续传。服务端读取前缀核对 MIME，分片收齐后校验完整长度和 SHA-256，再通过 storage 写入平台隔离存储。业务批准单独授权，发布仍需符合保护要求及健康副本门槛。

客户端可预先查询当前身份有权使用的用途清单、允许类型、单文件大小、会话时限和打包上限。响应省略内部隔离及发布密级。上传超过用途、会话或网关大小上限时返回 HTTP 413。

审核驳回使用独立的 `media.versions.reject` 权限与固定原因枚举，将待审版本置为 `rejected`、记录原因、释放待发布引用并调度清理。已批准、已有发布引用或仍需业务保留的版本拒绝按待审驳回处理。

审核读取通过 `GET /api/v1/media/versions/{id}/review-content` 获取已校验字节。首字节输出前重新核对 `media.versions.review` 权限和实际副本保护分类，并写入审计。审核读取不改变批准和发布状态。

## 引用与交付

引用固定到文件版本、所属模块和业务对象。引用所属模块须与上传用途一致，跨业务复用另建版本。仅 `active` 的引用可下载，`released` 为终态。

发布先保存意图，再检查当前业务授权、发布保护要求和健康副本数。新文件达到两份健康副本后可确认引用，目标为三份。崩溃后的重试沿用同一意图，激活引用仍需有当前授权的业务请求。

下载仅通过引用网关。存储完成整文件校验后，media 在首字节前再次检查文件停用、引用状态、业务权限和存储分类。单文件下载支持 HEAD、强 ETag、条件校验、Range 区间续传，以及对安全白名单类型的受限内联预览头；每次请求均重新校验当前权限，错误响应保持 no-store，没有开放直链或离线许可。

停用文件阻止新上传、引用和下载。释放仅停止对应引用的交付。仍有引用或所属业务要求保留源文件时，整文件删除返回冲突。迟到的写入或发布结果不得复活已删除版本。

## 源文件保留与恢复发布

释放最后一个待发布或活跃引用，或扫描到期且无活跃引用的版本时，media 通过装配方提供的 `SourceRetention` 回调查询所属模块。保留决定为真时保留源文件。查询失败会返回错误，操作不进入回收流程。

恢复发布使用 Go 接口 `AttachPublication`。同一发布操作重放使用原引用 ID，新发布操作使用新引用 ID。调用方可用 `RetirePublication` 按原发布操作标识释放引用，即使旧的附加响应丢失。当前开放的 HTTP 附加接口仍按版本和业务绑定使用稳定引用 ID。

## 清单与打包

文件清单按上传者与创建时间倒序分页，支持按用途和最新版本状态筛选，单页最多一百项并逐项检查全部版本的保护要求。文件详情与状态修改也覆盖全部版本保护分类。

每项包含版本数量与最新版本摘要；部分行无权读取时在五倍页长上限内自动补齐，游标按已扫描行推进且不泄露存储位置和凭据。

下载包仅接受业务引用，默认最多一百份文件、总大小 1 GiB，部署可降低上限。每个文件输出前重新检查当前权限，结束前再次检查整份清单；撤权或传输失败会中断下载，客户端须丢弃不完整文件。

ZIP 使用原文件名和独立编号目录，避免同名覆盖，支持过滤后的自定义压缩包下载名称。manifest.json 保存文件名、版本、长度、SHA-256 与预估压缩包字节数。打包复用 storage 的有界校验暂存，不保存完整 ZIP，整个请求只占一个传输名额，最长期限仍为五分钟。

## 持久化与恢复

文件内修改串行化，传输不占用长期数据库事务。上传与恢复均使用持久化租约及执行代次，过期执行者不能覆盖已批准或终态版本；扫描不中断有效租约内的上传，已完成会话对异键或异体请求返回冲突，verifying 重试优先核对存储结果。稳定存储键绑定服务身份和文件版本，不生成第二对象。

删除先停止本地交付，再释放版本持有的存储引用并清理句柄。恢复时重新核对引用，以处理迟到发布。`cleanup_complete` 表示版本的存储句柄已经清理或从未建立。

其他版本仍使用同组内容时，副本继续保留。最后一个共享内容句柄释放时，确认物理删除后才报告清理完成。审核、引用事件和模块状态在同一事务内提交。

## 资源与保留

每个用途明确文件大小和允许类型；单文件上限 1 GiB，传输并发最多 16，单次执行最多五分钟。上传会话一至一千四百四十分钟；无业务引用的孤儿版本与绑定待审引用的版本分别配置保留期限，均不超过二十四小时及存储核心临时对象窗口。

首次申请存储句柄时保存固定保留上限。后续绑定不能延长到该上限之后。历史版本缺少上限时沿用已有保留期限。

每个身份最多一万个逻辑文件、一百个未完成上传，每文件最多一百版本，每版本最多一百绑定；实际配置可更低。校验与配额失败返回细粒度脱敏错误码及可选上限数值，传输并发繁忙返回 503 与 Retry-After 指引头。扫描与事件分页最多一百项，重试次数明确配置，耗尽后保留故障状态，不无限重发供应商操作。

分片续传使用有界私有目录保存暂存文件，其他下载与打包使用 storage 暂存。逻辑文件、墓碑与审计由模块数据库保存。

受 media.maintenance 保护的运维接口汇总任务与未投递事件积压，支持按执行代次重置阻塞任务，并分批有界清理到期幂等记录与已确认 outbox 事件，保留不可篡改审计。Readiness 检查数据库及存储状态可达性，可选观测钩子记录脱敏操作指标与追踪标识。

启用文件单独记录启用事件。取消与过期仅释放仍有效的引用，并逐条记录释放事件。运行身份检查包含 schema 属主角色、建表和审计截断权限。

完成响应保留 24 小时，到期后可再次使用原键。运维清理同时检查配置的历史保留期限和重放到期时间。扫描按页清理过期响应，旧记录从首次迁移起保留一个完整窗口。

上传检查最多读取 3072 字节识别文件签名及常见文档容器。Markdown 和 TeX 使用纯文本特征，具体 MIME 仍须在用途白名单内。启动时校验配置中的类型是否受支持。

恢复失败后从 5 秒起指数退避，最长等待 5 分钟。定期扫描保留退避时间。耗尽次数后，终态清理也保存脱敏错误码，并在同一事务中记录任务阻塞事件。

元数据、授权、恢复与传输操作均使用配置的执行期限。关闭服务会取消已开始的操作，并在调用方的关闭期限内等待退出。传输并发名额只约束传输和恢复任务。

Outbox 按持久序号读取。事务提交时通过 media_outbox 唤醒 relay。调用 PendingOutbox 可在分页前排除至多一千个退避主题。引用事件携带文件、引用及业务绑定标识。可选学校 ID 来自服务端用途配置，追踪上下文由装配方传入。

首次迁移按同一主题的历史修订顺序回填投递序号，后续执行迁移保留序号与确认状态。

文件最后一个版本完成清理后立即归还文件配额，并从默认列表移除。墓碑保留历史身份，迁移会识别已有清理结果。引用上限按仍有效的绑定计数，已释放绑定仍可查询。

只读接口用 PostgreSQL 单语句快照读取文件、版本或引用，在事务外执行授权。每次生成清单只批量查询一次，并按请求顺序返回。打包仍逐项核对首字节权限，结束前重新批量核对清单。

文件名须可在 Windows 解压。旧版本不兼容的名称保留在清单中，ZIP 内使用编号目录及 document。HTTP 路由错误返回 JSON 并保留 Allow，请求结束时清除读写期限。

候选查询索引以文件拥有者为首列，随后按内容特征和版本 ID 排序。迁移从所属文件回填拥有者，数据库触发器兼容旧写入端。

## 本人内容复用

新上传版本通过 storage 的共享内容引用保存。物理内容按存储服务身份、学校范围、保护要求、摘要、长度和副本策略分组，各版本仍独立保存文件名、上传者、审核和业务引用。旧版本保持原对象身份与恢复方式。

创建上传时可启用 `reuse_existing`，省略时按 `false` 处理。服务只在本人相同用途、内容类型、大小、摘要和当前用途配置中查找最多十个已完成候选，并重新检查读取权限、停用状态和保留期限。匹配后免传输文件字节，新版本继续等待独立业务审核。

创建免传会话后，若名额不足或暂时无法确认存储结果，接口返回已持久化的 `verifying` 会话。`reused` 为 `true` 且状态为 `verifying` 时，客户端查询原会话等待恢复，无需发送文件字节。

来源存储探测在创建事务外执行。来源与目标保护要求不同会在服务端校验并迁移内容，同一保护分组复用已有副本。响应丢失和重启后沿用原版本与存储引用。

跨用户仅提供摘要不获得免上传或内容读取。用户实际上传并通过完整字节校验后，相同保护分组可以共用副本。来源权限被撤销、文件停用或用途配置变化时，不再选择来源免上传。
